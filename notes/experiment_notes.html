코드 만져보기 — 실험 노트

완성된 코드를 읽기만 하지 않고, 한 줄씩 바꿔서 결과가 어떻게 변하는지 확인한 기록. 개념을 '몸으로' 이해하는 방식.

왜 이렇게 배우나 — 3개 층위

코드 배움엔 ①개념(왜 이렇게 푸나) ②흐름(데이터가 어떤 모양으로 흐르나) ③문법(도구 사용법) 3층이 있다. 문법을 한 줄씩 완벽히 외우는 건 지금 단계엔 비효율 — 개념은 이미 잡았고, 문법은 만져보면서 자연히 익는다.

실험 1 — descriptor를 망가뜨리면 B가 무너질까?

바꾼 코드 한 줄: X = data['descriptor'][tr] → X = np.random.permutation(data['descriptor'])[tr] (각 perturbation에 엉뚱한 특징을 붙여 짝을 파괴)

예측: B가 무너져 A 기준선 수준으로 추락할 것
모델MAE↓PDS↑DES↑
A (기준선)0.5940.00.792
B (정상 descriptor)0.1861.00.923
B (뒤섞은 descriptor)0.5590.4290.784

→ 예측 적중. 정상 B(MAE 0.186)가 descriptor를 뒤섞자 0.559로 3배 악화 — 거의 A(0.594) 수준.

교훈: 데이터에 구조가 있어도, 모델이 올바른 입력(descriptor)을 받아야 이긴다. 대회에서 descriptor = "어떤 유전자를 껐나 + 그 유전자 특성" → 어떤 특징을 입력으로 쓸까가 승부의 큰 부분.

실험 2 — 훈련 데이터를 줄이면 B가 얼마나 나빠지나?

바꾼 것: 훈련 perturbation 수를 16 → 8 → 6 → 4 → 3 → 2로 축소.

예측: 점점 나빠질 것
훈련 수MAE↓PDS↑
20.4630.786
30.3980.75
40.4390.929
60.4790.964
80.3411.0
160.1861.0

→ 큰 방향 적중(16개=0.186 최고, 줄일수록 악화). 반전 두 가지:

반전 1: descriptor가 4차원 → 절편 포함 미지수 5개. 훈련이 5개보다 적으면(2~4개) 정보 부족으로 규칙을 온전히 못 정해 성적이 들쭉날쭉·운에 좌우. 미지수보다 데이터(방정식)가 많아야 안정적으로 풀린다 — 데이터가 왜 필요한지의 수학적 이유.

반전 2: 그래도 2개만 있어도 A(0.594)보다는 나음(0.463). 학습형은 데이터가 적어도 완전 무용은 아니나, 진짜 힘은 충분한 데이터에서.

실제 대회로 연결

두 실험이 같은 곳을 가리킨다 — 학습형 모델의 성능 = 좋은 입력 특징(descriptor) × 충분한 데이터. STATE가 수억 세포로 학습해 강한 것도 실험 2의 원리다. 모델을 키우면(파라미터↑) 데이터도 그만큼 더 필요하다(미지수↑ → 방정식↑).
